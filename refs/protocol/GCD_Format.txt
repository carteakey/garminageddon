Garmin GCD Firmware Update File Format
Filename extension *.gcd

This documentation is based on own research and the sources listed in the references section.


Basic data types
All values are serialized in little-endian byte order (least significant byte first).

Type          Length     Description
char          1          ASCII character (see [6])
byte          1          8 bit unsigned integer (range 0 .. 255)
ushort        2          16 bit unsigned integer (range 0 .. 65535)
uint          4          32 bit unsigned integer (range 0 .. 4294967295)

Version:
An ushort where the value is calculated as major version x 100 + minor Version.
E.g. 0x0064 = 100 = V1.0

Compressed part number (see [1]):
The 9x8 bits have to be interpreted as 12 character codes with 6 bits each.
Example: 10 D4 40 56 14 91 0D 14 41
Reverse bytes (shown in binary format with most significant bit (bit 7) first):
0100 0001 0001 0100 0000 1101 …
Create groups of six bits each:
010000 010001 010000 001101 …
Add 0x20 = 0010 0000, this may overflow into the 7th bit:
00110000 00110001 00110000 00101101 …
Interpret bytes as ASCII code:
    '0'      '1'          '0'      '-' ...

The region byte in an RGN file (see my other document Garmin_RGN_Format) corresponds to the least
significant byte of the Record ID in the range 0x0500 to 0x05FF. Additionally, Record ID 0x0008 corresponds
with region 0x0C, and Record ID 0x02BD corresponds with region 0x0E.

Copyright*)+, End

* = zero or more occurrences, + = at least one occurrence

CheckPoint Records and Filler Records may be inserted anywhere in this sequence.

Firmware Data records must cover the complete Length as indicated in the Firmware Descriptor (and may
be missing altogether when Length=0).


CheckPoint Record (ID=0x0001)
Seen lengths: 1 and 4

If Length = 1, the content is a checksum byte.

Can appear anywhere. The content byte is chosen so that the sum over all bytes from the start of the file up
to and including the CheckPoint Record is 0x00. It’s a way to verify file integrity up to this point.

If Length is 4, the content is maybe CRC32?


Filler Record (ID=0x0002)
Length varies, content is always empty (0x00).

Can appear anywhere.


Part Number Record (ID=0x0003)
If Length= 2, the value is 2 bytes HWID

If Length= 9, the value is 9 byte compressed part number

Is always = 0x10, 0xD4, 0x5C, 0x13, 0x04, 0x45, 0x0D, 0x14, 0x41 = “010-10037-00”


Copyright Record (ID=0x0005)
ASCII string, not 0-terminated.


Firmware Descriptor Type Record (ID=0x0006)
Length is multiple of 2.

This is a sequence of field descriptions, each being 2 byte long.

The following Firmware Descriptor Record then contains a sequence of field values, that exactly follows this
regarding type and meaning.

Type             Content
byte             Field ID
byte             Field type

Note: For the same Field ID, the meaning is sometimes different depending on the Field type!

Firmware Data Record (ID varies)
The Firmware Descriptor Record contains the length of the firmware stream. This length can be much more
than what a single Firmware Data Record may hold, so there are as many Firmware Data Records following
until the complete firmware stream is done. The total length of a firmware stream is sometimes four more
than the size indicated in the Firmware Descriptor Record.

Each Firmware Data Record can hold up to 0xFFFF byte, but the usual length, except for the last record of
course, is 0xFF00. But other lengths have also been seen on the first record:

0xFF08, 0xFF40

The Record ID varies (see Record ID table above), but it is the same across all Firmware Data Records
belonging to one firmware stream. The same Record ID can appear multiple times in a GCD file, so it is more
a firmware stream type than a unique identification.


End Record (ID=0xFFFF)
Length is 0.
