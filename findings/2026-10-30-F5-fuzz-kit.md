- Wrote `refs/tools/fuzz_harness.py` with three subcommands: `baseline` (ro snapshot of the crash oracle), `inject` (**user-invoked only**: prompts for the word INJECT, mounts rw, refuses overwrites without `--force`, copies ONE mutant to the type-mapped dir, forges `.sum` for voice files, fsync+sync, unmounts, prints the device procedure, appends to an on-host ledger), `collect` (ro; diffs Shutdowns dir + shutdown.log vs baseline; reports new records with cause code, error number, 16-register nonzero count, RTL source line, call stack; exit codes 0 clean / 2 new-RTL-Trap / 3 weak signal / 1 error). `findmnt`-guarded: baseline/collect remount a stray rw mount to ro before reading.
- Captured the **pre-fuzzing baseline** from the device and stored it in `refs/fuzz-corpus/baseline/`.
- Smoke-tested the full `collect` diff path against a doctored baseline copy in /tmp (stripped hashes) — correctly re-detected the real 2014 RTL_Trap from live device data (verdict 2) and a clean run (verdict 0). `inject` was NOT executed (by design).

### Format intel discovered along the way (device log / voice checksum)

- **`shutdown.log` quirk:** records contain the **literal string `|NEWLINE|`** instead of real newlines, and timestamps are unpadded (`2014-5-2 9:43:23`, `17:1:1`). Framing = back-to-back records starting `RECORD_SIZE: {N}ParserVersion 3`; `N` ≈ record bytes excluding the RECORD_SIZE line (970-B records measured at 989 B with prefix). Cause-1 records carry `Error Number: 0x…` + 16 registers inside `RTL_Trap_Info` (no CPSR in the log — that's HTML-only).
- **`Voice/*.sum` cracked:** it is a plain **u32 little-endian additive sum of the matching `.vpm` bytes** (exact match on both test voices: Michelle `00e2a20e` = sum32le 0x0ea2e200; Cantonese `00dc8905`). Consequence: a mutated `.vpm` + harness-forged `.sum` passes the loader's integrity gate — the voice parser can be fuzzed without any crypto barrier.
- Trap HTML parses to: error number, RTL source line (`gpk\tsk_emb_lib\tsk_mem_mmu.c 503, INVALID task handle.` for the 2014 crash), task id (`SYC main`), uptime, 14 call-stack addr:offset pairs.
- Baseline log has repeated identical records (RTC-reset triplets, year **2126**) — `collect` therefore diffs by record hash **and** detects pure log growth, so "device shut down again with identical content" is still flagged.
- Actual GPX dir is root-level `/GPX/` (dossier/attack-surface said `Garmin/GPX/`); boot-import target for fuzzing remains `Garmin/GPX/` (user area, created by inject on demand).

## Results / conclusions

### Tool usage (the whole loop)

```bash
# batch of 10 mutants (deterministic; same --rng = byte-identical output, verified)
python3 refs/tools/fuzz_mutate.py refs/fuzz-corpus/seeds --out /tmp/mut -n 10 --rng 1
# jpeg-only batch:  fuzz_mutate.py refs/fuzz-corpus/seeds/jpeg --out /tmp/mut -n 10 --rng 2

# USER runs inject (prompts for INJECT; mounts rw, copies, syncs, unmounts, prints procedure)
python3 refs/tools/fuzz_harness.py inject --file /tmp/mut/Garmin_Asia.m0003.jpg

# USER on device: unplug → power on → trigger (boot for GPX / slideshow for JPEG /
# voice-select for VPM / vehicle-select for SRF) → observe → replug

# HOST: diff the crash oracle vs baseline (mounts ro)
python3 refs/tools/fuzz_harness.py collect --json /tmp/diff.json
# exit 0 = clean, 2 = NEW RTL_Trap (crash!), 3 = weak/ambiguous, 1 = error
```

### Exact user-in-the-loop procedure (per cycle — one mutant on device at a time)

1. `inject` (host, user-authorized) — copy ONE mutant; the harness logs dest+md5 to `refs/fuzz-corpus/injected.log`.
2. Unplug nüvi; power on (external power — battery is EOL); run the trigger for that file type (see PLAN.md table: boot-import / slideshow / voice-select / vehicle-select).
3. Observe ONE of: normal · silent skip · app error dialog · crash+restart · hang/freeze · reboot loop. Note it.
4. Replug; run `collect`. exit 2 = crash — save the mutant as `CRASH-<name>` in results.md and re-run the cycle once to confirm reproducibility (same `--rng` regenerates it byte-exact).
5. Log the cycle in `refs/fuzz-corpus/results.md`; rollback = delete the injected device path(s) from `injected.log` (PC file manager over USB, or device UI); voice = delete both `X.vpm` and `X.sum`.
6. Hang/no-boot recovery: connect USB (25x5 enumerates mass storage regardless of GarminOS boot state), delete the file; worst case hold power 10 s, reconnect. Verify with `collect` → exit 0.

Priority order + expected-signal table + rollback details: `refs/fuzz-corpus/PLAN.md`. GPX-first (parsed every boot = fastest loop), then JPEG, then VPM (now gate-free thanks to the `.sum` finding), SRF, TYP/img deferred.
